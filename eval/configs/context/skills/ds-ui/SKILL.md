# ds-ui — экраны из компонентов ViennaUI

## Режим работы

Определи режим по запросу и не выходи за его рамки.

| Режим | Когда | Что делаешь | Чего не делаешь |
|---|---|---|---|
| **Build** | «сделай экран», ссылка на фрейм Figma, описание экрана | собираешь экран | не меняешь DS и чужие экраны |
| **Review** | «проверь экран» | список нарушений с ID правил и уровнем P0–P3 | не правишь код, пока не попросят |
| **Copy** | «поправь тексты» | меняешь только строки | не меняешь вёрстку |

## Порядок источников при конфликте

1. Явная цель пользователя в задаче.
2. Макет в Figma (если задача по макету): структура, состав, тексты.
3. Документация компонента в Storybook MCP: какие пропсы и варианты существуют.
4. Правила из `references/rules.md`.
5. Примеры из `exemplars/`.
6. Общие эвристики — только если выше ничего нет.

## Процесс Build

1. **Источники.** Назови, что загрузил: этот skill, `references/*`, Storybook MCP, Figma MCP.
2. **Состав экрана.** Выпиши список блоков экрана и для каждого — компонент DS.
   - По макету: `get_design_context` для фрейма. Если пришёл Code Connect-сниппет — используй его как есть.
   - По описанию: найди компоненты через Storybook MCP (`docs-list`, затем `docs-show` для каждого).
   - Блок без подходящего компонента → **стоп, спроси**. Не создавай свой.
3. **Сборка.** Пиши экран, проверяя каждый проп по `docs-show`. Раскладку — компонентами раскладки DS; если их нет, `div` с токенами отступов.
4. **Story.** Добавь `Screen.stories.tsx` с `Default`. Если у экрана есть состояния (загрузка, ошибка, пусто) — по story на каждое.
5. **Проверки.** `npm run typecheck`, `npm run lint`. Если доступен Storybook MCP — `test-run` для story экрана.
6. **Чек-лист** ниже. Каждый пункт — да/нет. «Нет» исправь до ответа.

## Чек-лист перед «готово»

- [ ] Все интерактивные элементы — компоненты DS (нет нативных `button/input/select/textarea/dialog/table`).
- [ ] Ни одного hex, rgb, px или `[…]`-класса; отступы — только `s1…s16`.
- [ ] Ни одного своего компонента, повторяющего компонент DS.
- [ ] Каждый проп существует в документации компонента.
- [ ] Каждое поле — в `FormField` с `FormField.Label`; ошибки — `FormField.Message color="critical"`.
- [ ] Обработчики `onChange`/`onSelect` компонентов ViennaUI принимают `{ value }`, а не DOM-событие.
- [ ] Не больше одной кнопки `design="accent"` на экране.
- [ ] Остальные правила из `references/rules.md` соблюдены; у иконок-кнопок есть доступное имя.
- [ ] Есть состояния ошибки и загрузки, если экран что-то отправляет или загружает.
- [ ] typecheck и lint без ошибок.

## Справочники

- `references/rules.md` — правила с ID. Ссылайся на ID в ревью.
- `references/components.md` — карта «задача → компонент DS».
- `references/coverage-gaps.md` — чего в DS нет и что делать.
- `exemplars/` — хорошие и плохие примеры.

# Как проводить прогон

Один прогон = одна задача × одна конфигурация × один номер попытки. План: 10 задач × 3 конфигурации × 2 попытки = 60 прогонов, плюс контроль в v0.

## Перед экспериментом (один раз)

1. `npm install`, `npm run eval:manifest` — список компонентов DS для анализатора.
2. `npm run test:tools` — инструменты измерения работают.
3. Дизайнер заполняет `figmaNode` для T01–T05 в `eval/tasks/tasks.json` и кладёт скриншоты фреймов в `eval/tasks/T0x/reference.png` (нужны для конфигурации A).
4. Зафиксируйте в этом файле модель агента и версии: Claude Code / Cursor, Storybook, Figma MCP.

## Прогон

Все прогоны идут в одной ветке `pilot-runs`, чтобы результаты собирались вместе.

```bash
git switch pilot-runs 2>/dev/null || git switch -c pilot-runs
rm -rf src/screens/T01            # чистый старт для задачи
npm run eval:config -- C          # A | B | C
npm run storybook                  # только для C, в отдельном терминале
npm run eval:prompt -- T01         # скопировать промпт
```

1. **Новая сессия агента**, вставить промпт без изменений. Время — с отправки промпта до «готово».
2. Агент может задавать вопросы — отвечайте только «используй то, что есть в дизайн-системе». Таймаут — 20 минут.
3. Не правьте код руками до замеров.

## Замеры

```bash
npm run eval:analyze -- T01 C 1
TASK=T01 CONFIG=C RUN=1 npm run eval:a11y     # нужен запущенный Storybook
npx eslint src/screens/T01 | tail -1          # число ошибок линтера — до исправлений агента, если он их не запускал
```

Строка в `eval/results/manual.csv`:

| Поле | Что писать |
|---|---|
| `time_min` | минуты до «готово» |
| `tokens` | токены сессии из интерфейса агента |
| `skill_loaded` | `да`, если агент сам назвал skill ds-ui среди загруженных источников (только C) |
| `lint_errors_first` | ошибки линтера в первом варианте агента |
| `review_edits` | сколько правок попросил ревьюер, чтобы экран можно было мержить |
| `reviewer_score` | 1 — переписать, 2 — много правок, 3 — мелкие правки, 4 — мержить как есть |

`eval:analyze` сохраняет копию экрана в `eval/results/screens/T01-C-1/`. Ревьюер не должен знать конфигурацию: передавайте ему файлы без названия папки.

```bash
git add -A && git commit -m "run T01 C 1" && git push -u origin pilot-runs
```

## Итог

```bash
npm run eval:report     # → eval/results/REPORT.md
```

## Контроль в v0

Те же задачи T01–T10 в v0 Design Systems 2.0 с подключённым пакетом DS. Код экрана положите в `src/screens/T0x/`, запустите `eval:analyze` с конфигурацией `A` и пометьте в `notes` manual.csv «v0».

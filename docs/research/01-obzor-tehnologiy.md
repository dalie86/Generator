# Дизайн-система становится исполняемым контекстом для агентов

На октябрь 2026 года выигрывает не один инструмент, а **связка из трёх слоёв**. Первый слой — дизайн-система (DS) как машиночитаемый источник правды: токены по W3C DTCG 2025.10, типизированные API компонентов, Storybook и Figma Code Connect. Второй слой — доставка этого контекста агенту через **MCP, CLI, Agent Skills и AGENTS.md/DESIGN.md**. Третий слой — генератор: v0 Design Systems 2.0, Lovable, Bolt, Builder.io Fusion, Figma MCP/Make, Claude Design, Google Stitch или агент в IDE (Claude Code, Cursor, Codex). Генерация идёт в цикле детерминированных проверок: линтер токенов, TypeScript, a11y и визуальная регрессия. Реальную привязку к вашим компонентам гарантируют только инструменты, которые импортируют настоящий npm-пакет или репозиторий и запрещают модели неподтверждённые компоненты. Инструменты на markdown-спеках (DESIGN.md, Library Styles, онбординг Claude Design) переносят в основном стиль, а не компоненты. Для UI, который генерируется во время работы приложения (runtime generative UI), лучшей практикой стал **декларативный пейлоад из каталога доверенных компонентов DS** (A2UI, json-render, OpenUI), а не генерация кода. Количественные результаты почти все получены от самих компаний на малых выборках. Самый устойчивый сигнал в них — **на 8–63% меньше токенов и времени** и резкое падение числа выдуманных компонентов при grounding'е. Практики на Medium описывают одно и то же: модель умеет работать с DS, но без явных правил и процесса выдаёт UI, который «выглядит правильно, но структурно неверен».

## Четыре способа подключить дизайн-систему к генератору

К 2026 году почти у каждого лидера есть формальный объект «Design System». Механизмы его подключения сильно различаются. Глубже всего работают **v0 DS 2.0**, **Lovable**, **Builder.io Fusion** и **Bolt**: они импортируют настоящий код. v0 при этом сохраняет DS как «skill» с файлом `v0.json` и действует по прямому правилу: **«если не может проверить компонент, проп или токен — не использует его»** ([v0 docs](https://v0.app/docs/design-systems-2)). Canvas-инструменты переносят в основном токены. В Figma Make kit типа «Library Styles» извлекает только стили, а компоненты приходят **лишь через npm-пакет**; это подтвердили сотрудники Figma на форуме ([Figma Forum](https://forum.figma.com/report-a-problem-6/make-kit-no-components-were-extracted-from-this-library-54140/index2.html)). Глубокая привязка к коду часто доступна только на Enterprise-тарифах: Lovable Path B, `index-repo` у Builder.io, маппинг компонентов в Locofy.

| Инструмент (релиз) | Выход | Как подключается существующая DS | Ограничения |
|---|---|---|---|
| **Vercel v0 — DS 2.0** (доки 27.10.2026) | Next.js + shadcn/Tailwind | GitHub-репо, npm (в т.ч. приватный), `.tgz`. Сохраняется как skill + `v0.json`, перед сохранением строится стартовое приложение на одобрение; только верифицируемые компоненты | Figma-фреймы служат лишь визуальным референсом; старые чаты не обновляются; на кастомных shadcn-компонентах возможны сюрпризы ([v0](https://v0.app/docs/design-systems)) |
| **Lovable Design Systems** (все платные тарифы, 08.2026) | React (TanStack) | Отдельный проект-DS: npm или Git; best-effort из PDF, MD или скриншотов. Копирует код в `src/design-system/`, правила в `.lovable/rules/` | Одна DS на проект, только React; обёртка над npm-пакетом — только Enterprise ([Lovable](https://docs.lovable.dev/features/design-systems.md)) |
| **Bolt — DS Agent** (30.04.2026) | React | Агент на Claude Agent SDK за один прогон забирает Figma, Storybook, GitHub и доки; компоненты вызываются через `@`; есть аудит проекта на соответствие DS | >10 000 команд — **цифра вендора** ([Create With](https://www.createwith.com/tool/bolt/updates/bolt-launches-design-system-agent-to-generate-production-ready-prototypes)) |
| **Builder.io Fusion** | React, Vue, Angular, Svelte → PR | `index-repo` индексирует компоненты и токены, режим Style Strict Mode | **~70% точности автомаппинга** (данные вендора); CLI и CI — только Enterprise ([Builder](https://www.builder.io/c/docs/component-indexing)) |
| **Figma MCP (`use_figma`) + Make Kits** (03–04.2026; Config India 10.2026) | Figma-фреймы; код Make | Агент рисует реальными компонентами и переменными; Kit = npm-пакет + `Guidelines.md`; в закрытой бете — код DS из GitHub/npm | Kit типа Library Styles не переносит компоненты; «грязная DS даёт грязный выход» ([Figma Help](https://help.figma.com/hc/en-us/articles/43602872461079-Bring-your-design-system-package-to-a-Make-kit), [Muzli](https://muz.li/blog/figma-just-opened-the-canvas-to-ai-agents-heres-what-it-means-for-designers)) |
| **Claude Design** (17.04.2026, research preview) | HTML, PDF, PPTX, handoff в Claude Code | На онбординге читает кодовую базу и дизайн-файлы и собирает DS команды | Конкурент UXPin называет его «аппроксиматором»: стилизует новое, а не использует реальные компоненты ([Anthropic](https://www.anthropic.com/news/claude-design-anthropic-labs), [UXPin](https://www.uxpin.com/studio/blog/ai-design-tools-ignore-design-system/)) |
| **Google Stitch** (03.2026) | HTML/Tailwind, Figma, MCP | Извлекает DS по URL, правила хранит в **DESIGN.md** | DS-интеграция мельче, чем у Figma; по умолчанию дизайны идут в обучение модели ([Nervegna](https://nervegna.substack.com/p/vibe-design-is-real-inside-google), [Classmethod](https://dev.classmethod.jp/ja/articles/new-stitch-ai-design/)) |
| **UXPin Forge, Subframe** | React (+Tailwind) | Генерация только из синхронизированных реальных компонентов (Merge: Git/Storybook/npm; CLI+MCP) | Мало свободы для исследования; обзоры написаны конкурентами ([Banani](https://banani.co/blog/subframe-ai-review)) |
| **Magic Patterns, Replit Design, Anima, Locofy, Framer 3.0** | Разный | Агенты DS сканируют источник; Locofy мапит Figma на код (Enterprise); Framer сохраняет токены проекта | Метрик нет; Framer плохо справляется со сложными приложениями |

Лёгкие canvas-инструменты (UX Pilot, Uizard, Visily, Banani) дают только темы-ползунки и не импортируют DS ([Banani](https://www.banani.co/blog/uxpilot-alternatives)). Почти все code-first инструменты генерируют React + Tailwind + shadcn. Для DS на Vue, Angular или Web Components реальных вариантов три: Fusion, Locofy или агент в IDE с Figma MCP. Отдельно стоит учитывать риск зрелости: Webflow App Gen закрыли через ~5 месяцев после беты ([Pravin Kumar](https://www.pravinkumar.co/blog/webflow-app-gen-deprecated-ai-code-components-pivot-2026)), а Tambo Cloud закрывается 31.10.2026 ([Tambo](https://tambo.co/blog/posts/introducing-tambo-generative-ui)).

## Стандарты 2026 года: MCP для доставки контекста, каталог для runtime-UI

Инфраструктура разделилась на два контура. **Build-time** контур отдаёт DS агенту, который пишет код или макет. **Runtime** контур рендерит интерфейс, который агент собирает на лету, компонентами вашей DS. В первом контуре задачу контекста решает MCP. Во втором протоколы A2UI, AG-UI и MCP Apps дополняют друг друга, а не конкурируют ([CopilotKit](https://webflow.copilotkit.ai/blog/the-state-of-agentic-ui-comparing-ag-ui-mcp-ui-and-a2ui-protocols)).

| Слой | Стандарт / инструмент | Статус на 10.2026 | Роль |
|---|---|---|---|
| Токены | **W3C DTCG 2025.10**; Style Dictionary, Tokens Studio, Terrazzo | Первая стабильная версия, Final CG Report ([W3C](https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/)) | Мультибренд, темы, OKLCH; экспорт из Figma variables только «DTCG-aligned» |
| Транспорт контекста | **MCP**; DS-серверы Primer, Carbon, Uber Base, Atlassian, shadcn, Storybook/Chromatic | MCP в Agentic AI Foundation (Linux Foundation) | Поиск компонентов, токенов, гайдлайнов и `lint_css` по запросу ([Primer](https://primer.style/product/getting-started/foundations/mcp)) |
| Инструкции | **AGENTS.md**, **Agent Skills (SKILL.md)**, DESIGN.md (alpha, Google) | AGENTS.md — более 60 тыс. репозиториев; DESIGN.md с CLI `lint`/`diff`/`export` в DTCG | Всегда включённые базовые правила и описание процесса ([Abduzeedo](https://www.abduzeedo.com/design-md-google-ai-design-tokens)) |
| Дизайн↔код | **Figma MCP + Code Connect** | Удалённый сервер, запись на холст, `search_design_system` ([Figma dev](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/)) | Маппинг Figma-компонентов на код |
| Документация | Storybook manifests, llms.txt (proposed), JSON API (Cloudscape) | Storybook AI в preview | Индекс → Markdown → JSON ([Cloudscape](https://cloudscape.design/get-started/for-developers/ai-tools-support/)) |
| Runtime-пейлоад | **A2UI** (Google, Apache-2.0) | v0.9.1 в продакшене, v1.0 RC; рендереры Lit, Angular, React, Flutter | Декларативный JSON только из каталога клиента; с v0.9 — «используйте существующую DS» ([InfoQ](https://www.infoq.com/news/2026/07/google-a2ui-genui)) |
| Runtime-пейлоад | **json-render** (Vercel), **OpenUI** (Thesys), Thesys C1 | json-render >13 тыс. звёзд | Каталог на Zod-схемах; OpenUI Lang на 52.8% экономнее JSON — **данные вендора** ([InfoQ](https://www.infoq.com/news/2026/03/vercel-json-render), [themenonlab](https://themenonlab.blog/blog/openui-generative-ui-framework-token-efficient)) |
| Runtime-транспорт | **AG-UI** (CopilotKit) | Используют LangGraph, ADK, MS Agent Framework, Mastra | Стриминг, события, общее состояние ([TechCrunch](https://techcrunch.com/2026/05/05/copilotkit-raises-27m-to-help-devs-deploy-app-native-ai-agents/)) |
| UI в чат-хостах | **MCP Apps (SEP-1865)**; OpenAI Apps SDK поверх него | Final, production-ready с 26.01.2026 ([SEP](https://modelcontextprotocol.io/seps/1865-mcp-apps-interactive-user-interfaces-for-mcp)) | HTML в обязательном sandbox-iframe; стиль задаёт сервер, а не DS хоста |
| SDK приложений | **AI SDK UI** (tool → компонент), LangGraph GenUI, assistant-ui, Flutter GenUI | `streamUI` (RSC) экспериментальный и не рекомендуется для продакшена ([ai-sdk.dev](https://ai-sdk.dev/docs/ai-sdk-rsc/migrating-to-ui)) | Маппинг вызовов инструментов на ваши компоненты |

Реальное внедрение пока тонкое. В аудите 37 крупных DS (сентябрь 2026) MCP поставляют 12 систем, llms.txt — 10, DTCG-токены — 6, Code Connect — 3, а **19 из 37 не набрали ни одного сигнала** ([designsystems.one](https://www.designsystems.one/ai-ready/systems)).

## Лучшая практика: маленькие правила всегда, большой контекст по запросу

Эталонный конвейер, на котором сходятся Atlassian, BILL, Uber, Vercel и Figma, устроен так. Единый версионированный источник (токены DTCG, типизированные пропсы, Storybook) собирается в общие модули. Из них в CI автоматически генерируются MCP-сервер, CLI и skill, поэтому ответы не расходятся. Atlassian подчёркивает, что общий код поиска «предотвращает дрейф» ([Atlassian](https://www.atlassian.com/blog/ai-at-work/giving-ai-agents-design-system-context-from-the-terminal-what-we-learned-building-a-cli)), а BILL пересобирает CLI и MCP при каждом изменении доков ([BILL](https://www.bill.com/engineering/how-we-made-our-design-system-bilingual)). Короткий AGENTS.md держит базовые правила (отступы, цвет, типографика), а API компонентов агент запрашивает по необходимости. Skill описывает **процесс**: проверить источник, найти компонент, запретить хардкод, эскалировать, если подходящего компонента нет. BILL прямо пишет, что поведение агентов изменилось, только когда skills описали workflow, а не просто дали доступ к данным. Дальше идут гейты от детерминированных к человеческим: `@shadcn/lint` (`no-raw-colors`, `no-arbitrary-values`), TypeScript, axe, Storybook `test-run`, скриншоты против Figma, затем AI-ревьюер PR и человек. Vercel формулирует принцип так: каждое исправление кладётся в **«самый узкий слой, способный его обеспечить»** ([Vercel](https://vercel.com/blog/how-our-agents-build-on-brand-pages-with-design-md)).

| Кейс (все данные — самоотчёт компаний) | Результат |
|---|---|
| Figma: Code Connect в MCP, 27 кейсов | Качество кода 2→3 по шкале 1–4, **−29.5% токенов, −19.6% времени**; эффект растёт с покрытием маппинга ([Figma](https://www.figma.com/blog/the-benefits-of-code-connect-in-mcp/)) |
| Atlassian: DESIGN.md vs MCP vs skill | MCP и skill используют ~80% контекста DS, DESIGN.md — ~30% при 7.2M токенов и разбросе в 2.7 раза ([Atlassian](https://www.atlassian.com/blog/how-we-build/atlassians-design-md-is-here-what-we-learned-testing-portable-design-context-in-practice)) |
| Atlassian: CLI vs MCP | ~8% быстрее и дешевле; агенты вызывают CLI на 60% чаще, чем MCP |
| BILL: 4 задачи | **−45% входных токенов**, правильные компоненты с первого прохода |
| Vercel: design.md + eval-цикл | Известных дефектов 91→39 (−57%), но на каждой странице остался хотя бы один блокирующий |
| Kaelig/Intuit: 8 агентов | 27 выдуманных CSS-токенов → 0 после трёх правил; компонент за ~1 час вместо ~2 дней ([kaelig.fr](https://www.kaelig.fr/design-system-components-with-ai-agent-teams/)) |

Ключевой вывод из этих кейсов: **монолитный DESIGN.md проигрывает поиску по запросу** в продакшен-задачах, хотя как переносимый формат стиля он полезен. Независимых бенчмарков соответствия DS нет. Академические Design2Code и WebGen-Bench (лучший результат 27.8%) измеряют только верность скриншоту и функциональность ([arXiv](https://arxiv.org/abs/2505.03733v2)).

## Что пишут практики на Medium: процесс важнее модели

Главная мысль статей с Medium: **сбой проявляется в структуре, а не в картинке**. Sen Lin описывает, как Claude Code через Figma MCP рисовал макеты с hex-цветами вместо токенов и с одноразовыми компонентами вместо инстансов. Такой результат проходит визуальное ревью и проваливается при структурной проверке. Автор лечит это четырьмя skills: Preflight строит карту токенов и реестр компонентов, Design Brief подтверждает дизайнер, Component Rules требует сначала искать компонент в библиотеке, Style Binding запрещает raw-значения и запускает QA-проход. Строгость правил зависит от режима: жёстко для артефактов, которые уходят людям, мягче для прототипов ([UX Collective](https://uxdesign.cc/how-to-make-claude-code-follow-your-design-system-in-figma-559618cffaa9)).

Повторяются несколько приёмов. Spec и инструкции стоит держать раздельно: DESIGN.md как справочник и короткий SKILL.md со ссылкой на него. Самопроверка по чек-листу из 12 пунктов устранила пропуски `prefers-reduced-motion` и хардкод радиусов ([Warsono](https://medium.com/@gravitano/i-built-a-claude-code-skill-that-turns-a-design-system-into-pixel-perfect-ui-heres-how-6d00c90daccd)). Каждый токен описывается как **«значение, назначение, граница»**. Около восьми запретов дают больше, чем объёмный раздел токенов, а бриф продукта пишет человек, иначе модель выдумывает принципы ([Demchenko](https://uxdesign.cc/how-to-write-a-design-md-file-claude-can-actually-use-2d89d183f823)). Правила формулируются бинарно, фраза «use your best judgment» ломает результат, и обязателен приоритет при конфликте источников ([Rashid](https://www.designsystemscollective.com/part-3-how-to-write-a-design-md-that-ai-coding-agents-actually-follow-eef25ca0369a)). Отдельная частая ошибка — считать, что агент прочитал файл. Его нужно подключить @-импортом в CLAUDE.md и проверить через `/context` ([UX Planet](https://uxplanet.org/7-design-md-mistakes-that-make-ai-generated-ui-worse-9ec2dfcc44cd)). В Figma ссылка на фрейм точнее ссылки на файл, а макет на variables даёт заметно лучший код, чем скриншот ([Sundaram](https://medium.com/@narayanansundar02/integrating-figma-mcp-with-cursor-live-design-context-code-generation-28a52743cdab), [Gadhia](https://uxplanet.org/new-figma-mcp-cursor-integration-with-example-46e0641400d6)).

Режимы сбоев описаны так же единообразно. Инструменты откатываются к shadcn, если DS построена на MUI или другой библиотеке: «чем дальше DS от дефолтов, тем больше усилий» ([Arteeva](https://annaarteeva.substack.com/p/design-systems-lovable-bolt-v0-and)). Stitch часто игнорирует DESIGN.md, выдаёт шаблонный вид, ставит hover на мобильные экраны, рассогласует экраны, а при экспорте ломает auto-layout. Авторы UX Planet используют его для идеации, а финал доводят в Figma + Claude Code ([UX Planet](https://uxplanet.org/google-stitch-for-product-designers-5b46b56c7c8c)). Figma Make, Lovable, Bolt и Anima почти единодушно названы инструментами исследования: перед продакшеном код переписывают ([Al-azzeh](https://medium.com/design-bootcamp/claude-code-figma-a-designer-developer-workflow-that-actually-works-b7d7545edc40), [Paschal](https://uxdesign.cc/vibe-code-straight-from-your-website-ce52eef25d95)). Центр тяжести к 2026 году сместился от конструкторов приложений к агентам в IDE с явным слоем контекста DS. Корпоративных метрик на Medium почти нет. Единственный количественный кейс — LLM-документирование DS у Yuti Vora: −85% времени на вариант и −70% вопросов разработчиков, это самоотчёт по одному проекту ([Bootcamp](https://medium.com/design-bootcamp/automating-design-systems-with-llms-how-ai-helped-me-scale-component-documentation-across-df4951a7ddfc)). Он показывает, что машиночитаемая документация окупается и как контекст для генерации.

## Выводы и рекомендации

Узким местом стала не генерация, а **готовность DS к агентам**. Инвестиции в структурированные токены, JSON-манифесты компонентов, Code Connect и skills, которые описывают процесс, переносятся между инструментами. Выбор конкретного генератора быстро устаревает, примеры Webflow App Gen и Tambo это подтверждают. Практический порядок такой. Сначала привести токены к DTCG и выпустить DS-MCP или CLI из общего ядра. Затем добавить короткий AGENTS.md и skill «найди компонент → не хардкодь → эскалируй». Затем поставить линтер токенов и визуальные и a11y-гейты. Для прототипов в React + shadcn подойдут v0 DS 2.0 или Lovable, для Figma-холста — Figma MCP с Kit на npm-пакете, для продакшен-кода — агент в IDE поверх репозитория. Для runtime-UI внутри продукта берите декларативный каталог (A2UI или json-render), а MCP Apps — только для UI сторонних инструментов в чат-хостах.

Остаются нерешёнными две вещи. Во-первых, нет независимого бенчмарка соответствия DS: все цифры выше — данные вендоров и компаний, поэтому их стоит проверить пилотом на собственных метриках (доля компонентов DS, число raw-значений, a11y-дефекты, токены на задачу). Во-вторых, даже лучшие конвейеры (Vercel −57% дефектов) не устраняют блокирующих ошибок, так что человеческий гейт пока остаётся частью архитектуры, а не временной мерой.
